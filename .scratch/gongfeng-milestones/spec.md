# 工蜂里程碑模块

Status: ready-for-human

## Problem Statement

用户需要在工蜂插件中统一查看和管理已添加仓库的里程碑、维护关联议题与 MR，并判断阶段进度，不希望逐仓库跳转原站。

## Solution

顶部增加里程碑入口，默认汇总当前工蜂实例的已添加仓库。紧凑列表按截止日期排列，详情使用悬浮抽屉；提供里程碑完整管理、关联草稿与分别统计的 Issue／MR 进度。内部工蜂优先，直接使用官方 OpenAPI，保持 Paseo 0.12 兼容和现有主题、手机体验。

## User Stories

1. 作为使用者，我能汇总查看已添加仓库的里程碑，并筛选单仓库。
2. 默认查看活动中，也能切换全部和已关闭，并搜索已加载标题、描述。
3. 列表显示仓库、标题、状态、截止时间、摘要及逾期信息，日期为空时后置。
4. 数据逐步加载，局部失败不清空其他仓库；搜索、排序与统计明确标识已加载范围。
5. 打开悬浮详情不挤压底层页面，有动画、可关闭、可刷新。
6. 我能在选定已添加仓库创建里程碑，填写标题、描述和可选截止日期。
7. 我能编辑、清空描述／日期、关闭和重新开启里程碑；不改变所属仓库。
8. 我能明确确认仓库及标题后删除里程碑；不附带删除关联议题或 MR。
9. 我能按需查看关联议题和 MR，查看历史状态，打开 MR 既有详情或议题原站。
10. 我能按关键词和项目内编号查找同仓库候选，形成添加／移除草稿，保存才写入。
11. 候选已有其他里程碑时显示原归属，明确确认后允许迁移；取消草稿不写入。
12. 保存前重新检查归属；归属已变化时提示刷新，不覆盖未知的新关联。
13. 分别展示 Issue 已关闭／总数、MR 已合入／总数，MR 已关闭未合入单列；不合并统一完成率。
14. MR 概览能看到关联里程碑并进入对应详情。
15. 我能区分无权限、空列表、网络错误、部分成功、结果不确定，并刷新核对。
16. 切换站点／账号后旧对象、在途结果及草稿不进入新身份，手机和深浅主题可用。

## Implementation Decisions

- 复用现有服务器凭据层和 RPC、原生卡片、弹窗、悬浮抽屉、富文本组件；不新增运行时依赖。
- 里程碑身份包含实例、账号、工蜂项目 ID、全局里程碑 ID；IID 只供展示／编号查找，重名不合并。
- 每仓库独立分页和错误，有限并发；详情关联项分页读取，不为所有列表行预取完整统计。
- 官方 HTML 与 Swagger 共同作为契约证据。MR 更新单数 merge_request，Issue 更新 issues，milestone_id 为全局 ID；查询参数位置及取消值需受控验证，不能照抄 GitLab。
- 写请求严格限定里程碑和关联字段，无任意方法／URL 透传，不允许旁路修改 Issue／MR 状态、分支、正文等。
- 写入不自动重试，检查当前身份和最新版本；关联保存预检查全部草稿，操作非事务，出现失败停止并回读实际结果。
- 删除确认与迁移确认分别显式表达。服务端执行授权，界面不猜测最小角色。
- 真实测试限定隔离样本，不修改实际业务对象，不调用模型，不自动发布社区新版本。

## Testing Decisions

用户已同意沿用现有 RPC 测试入口、外部 HTTP 边界及界面验收方式。测试真实注册的业务 RPC，使用临时凭据目录，仅替换工蜂 HTTP；覆盖分页、身份、错误、版本变化、CRUD、字段白名单、取消值、关联迁移和部分结果。不测试内部私有方法。

真实接口验证先只读定位专用 e2e 仓库，然后使用本轮独立样本验证写契约并清理。真实 UI 验证桌面、窄屏、深浅主题、浮层、草稿取消、删除确认和唯一刷新入口。最终运行统一检查和正式 Standards／Spec 审查，未验收内容明确列出。

## Out of Scope

未添加仓库扫描、项目组共享里程碑、统一完成率或燃尽图、TAPD 任务接入、创建／删除议题和 MR 的产品功能、MR 内 Agent Review 派发、自动合入／触发流水线、自动社区发布。

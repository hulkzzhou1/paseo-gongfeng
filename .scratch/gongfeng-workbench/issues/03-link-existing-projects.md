# 03: 仓库与已有项目关联

**What to build:** 用户搜索工蜂仓库并关联已有 Paseo 项目，也能从项目入口关联仓库；关系持久保存，解除关联保留现有资源。

**Blocked by:** 01 — 连接工蜂账号。

**Status:** ready-for-human

**规格依据：** [首期实施规格](../spec.md)，用户故事 5、6、8–12。项目列表复用宿主能力，工蜂仓库查询复用任务 01 的连接；本任务可独立于 MR 看板验收。

- [x] 仓库管理支持搜索有权限访问的工蜂仓库，区分查询失败、分页和空结果；可列出当前 daemon 已有 Paseo 项目及必要的定位信息。
- [x] 仓库和项目两侧入口维护同一份持久关系，标识使用工蜂实例与工蜂项目 ID、所属 daemon 与 Paseo projectId，不靠显示名唯一匹配。
- [x] 同一工蜂仓库可关联多个项目，每个 Paseo 项目最多关联一个工蜂仓库；重复添加同一关系不生成重复项，冲突时要求明确更换，不静默覆盖。
- [x] 自动匹配只提供候选，正确处理 SSH/HTTPS remote、子组和大小写；多个候选由用户选择，不取第一个。
- [x] 关系在插件重载后仍可用；项目失效、访问变化或 remote 不再匹配时呈现需核验状态，不擅自更换归属。
- [x] 用户解除选定关联后，仅关系记录被删除，本地代码、Paseo 项目、工作区和历史 Agent 保留。
- [x] 业务 RPC 集成测试覆盖一对多约束、冲突更换、重复添加、持久化失败、失效项目和解除关联；临时目录中的用户文件不受影响。
- [ ] 完成类型检查、两侧入口和深浅主题/紧凑布局检查；以真实宿主项目列表核验身份映射，避免将同 remote 的两份 clone 误当作一个项目。

**执行边界：** 不创建新项目或 clone，这由任务 04 提供；不修改宿主项目全局身份模型，不访问其他插件配置。插件内移除关联不等同删除仓库。

# 07: 独立工作区 Review 派发

**What to build:** 用户从 MR 详情选择一个关联项目和现有 Agent 预设，补充要求后启动新的 Review，在独立工作区审查固定版本，并在 Paseo 查看结果；失败可恢复，降级必须由用户选择。

**Blocked by:** 03 — 仓库与已有项目关联；05 — MR 详情与审查上下文。

**Status:** ready-for-human

> 历史任务：2026-10-23 用户决定移除 MR 内 Agent Review 派发，当前不再交付本功能。见任务25。下文保留历史实现和验收证据。

**规格依据：** [首期实施规格](../spec.md)，用户故事 22–31。本任务可使用已有项目，不依赖任务 04 的 clone，也不依赖任务 06 的附加信息；可用附加信息不是成功派发的强制前置。

- [x] 详情页可打开派发窗口，展示 MR、版本、关联项目和现有预设，并允许补充审查要求；没有关联时引导完成关联，不静默在任意项目启动。
- [x] 一个有效关联项目自动选中，多个时由用户选择一个；项目失效、remote 变化或关联冲突时要求核验，不静默取首个或改派。
- [x] 将选定预设的 provider/model、运行模式、思考配置及可用特性准确用于新 Agent；不向正在处理其他任务的 Agent 注入提示。
- [ ] 在实现默认路径前验证固定 SHA、比较基准、Git 访问及独立工作区创建的实际能力；源代码、差异与所审版本一致，MR 后续更新不改变正在进行的 Review。
- [x] 支持 fork 的源目标仓库区分及源代码获取；仍保持一个 Paseo 项目最多关联一个工蜂仓库，不假设 GitHub MR ref 或未发布的工蜂 checkout 支持。
- [ ] 工作区归入所选项目，保留用户原 checkout 的分支、未提交修改及文件；Review 通过独立工作区读取完整仓库。
- [x] 获取代码或可靠版本失败时显示具体原因，由用户明确选择是否仅基于已有 diff 审查；降级使用独立任务环境并标明完整性/版本限制，不暗用原开发目录，不虚构 SHA 或完整仓库验收。
- [x] 每次操作仅创建一个新 Review；重复提交受控。工作区创建成功而 Agent 启动失败时显示已有资源；恢复前核对资源，避免重复工作区或 Agent。
- [x] 审查任务包含 MR 上下文、版本、获取时间、完整性限制、补充要求及执行边界，不包含 Token。说明允许相关本地测试和静态检查及产物，不自动修复业务代码、访问共享环境、回写评论或触发远程操作。
- [x] 新 Agent 及其结果在 Paseo 中可达，结果说明所审版本、发现、实际执行的检查和未验证项。历史结果不能冒充新版本结论。
- [x] 业务 RPC 测试覆盖项目选择、预设应用、失效关联、重复提交、部分失败和恢复；临时真实 Git 仓库覆盖固定版本、分支移动、fork、权限失败模拟与原目录脏文件保护。
- [ ] 完成类型检查及真实宿主最小 Review 会话，核对实际工作区 SHA、Agent 配置、结果入口和执行边界；不以提示词文字断言替代行为验收。

**执行边界：** 固定版本和 fork 获取是技术前置验证，不能凭 mock 通过就认定真实宿主支持。Agent 仅按审查任务运行，远程评论、批准、合入、推送及流水线触发不在本任务范围；凭据不会放入 Agent 环境或 Git 参数。

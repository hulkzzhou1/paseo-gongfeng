# 05: MR 详情与审查上下文

**What to build:** 用户从 MR 看板进入详情，查看描述、分支、差异、讨论和审查状态，了解上下文完整性及可核验的版本信息。

**Blocked by:** 02 — 全局 MR 看板与历史查询。

**Status:** ready-for-human

**规格依据：** [首期实施规格](../spec.md)，用户故事 18、21、25 的上下文及版本部分。复用已选 MR 的身份和连接；TAPD/CI 附加区块由任务 06 提供。

- [x] 看板条目可进入详情，展示描述、源目标项目与分支、文件差异、讨论及审查状态，并可返回看板或打开原站。
- [x] 根据官方及真实响应区分工蜂项目 ID、MR 全局 ID、项目内编号和 Review ID，使用对应路由；不由界面编号猜测 API 身份。
- [x] 核验差异、评论及嵌套讨论的分页与完整性；截断、折叠、过大差异和未加载页明确标记，不向用户或后续 Review 声称上下文完整。
- [x] 获取并记录源仓库、源提交、比较基准及上下文获取时间；核验差异属于该版本。MR 在读取过程中变化时重新核对或标记不一致，不混合不同版本。
- [x] 版本信息不可证明时明确标为未知，不把分支名、Review ID 或当前任意提交当作 SHA；为后续派发提供可辨识的完整性状态。
- [x] 描述、评论及外链按不可信内容呈现，不执行内嵌命令或脚本，不将工蜂凭据用于任意外链请求。
- [x] 详情区块各自处理失败和空结果；评论或审查状态失败不清空已加载的描述和差异，错误可识别并可重试。
- [x] 业务 RPC 集成测试覆盖 ID/编号路由、讨论分页及嵌套结构、文件新增/删除/重命名、截断和版本变化、局部失败及不可信内容。
- [ ] 完成类型检查、真实详情界面和紧凑布局检查；对安全选定的 MR 做只读契约核验，仅保留字段结构与验证结论，不保存私有正文。

**执行边界：** 不写评论、不改变审查状态，不创建 Agent。可靠源 SHA/比较基准若无法取得，要保留证据并明确对固定版本 Review 的阻塞，不能伪造版本绕过。

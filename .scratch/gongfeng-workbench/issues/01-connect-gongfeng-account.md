# 01: 连接工蜂账号

**What to build:** 用户在可加载的 Paseo 工蜂插件中输入、验证和更换 Private Token，看到当前账号及连接状态，凭据只由服务端保存。

**Blocked by:** None (can start immediately).

**Status:** ready-for-human

连接功能已实现，视觉验收仍待人工完成。

**规格依据：** [首期实施规格](../spec.md)，用户故事 1–4；本任务建立后续功能复用的最小宿主入口和 OpenAPI 调用能力，不预建无需求的框架。

- [ ] 插件兼容实际 Paseo 0.12，在宿主加载成功，设置入口可用；采用宿主原生组件、有效图标、深浅主题及紧凑布局。
- [x] 设置页支持输入、验证和更换 Token；提交后清除输入，仅展示连接状态和当前账号，不回显已保存的 Token。
- [x] 服务端通过工蜂官方 OpenAPI 获取当前用户，区分未配置、认证失效、权限不足、网络错误及响应异常，不沿用 GitHub 凭据或 MCP。
- [x] 新 Token 验证或保存失败时保留原有可用配置；成功后更新账号并清理旧身份缓存。后续业务复用相同身份及错误处理约定。
- [x] Token 持久化位于仓库外的服务端受限存储，不进入普通共享设置、客户端持久缓存、日志、源码、错误响应、Git 参数或 Agent 环境。
- [x] 业务请求仅访问固定可信工蜂主机，不提供任意 URL/方法透传，不携凭据跨域重定向；不把 PAT api 范围称为平台强制只读。
- [x] 通过业务 RPC 集成测试验证成功和失败路径、配置替换与敏感信息隔离；使用受控 HTTP 响应和临时存储，完成类型检查及实际设置页检查。
- [x] 使用用户通过安全设置提供的 Token 完成首次真实只读当前用户请求，记录账号字段结构、认证方式和结果；证据不含令牌及私有内容。未获凭据时如实保留此验收未完成，不以模拟测试替代。

**执行边界：** 每个 daemon 一个账号。仅建立内部插件，不发布公共包，不创建远程事项，不读取其他插件秘密。当前实现前置事实为真实 Token 契约；缺少凭据时先完成可独立验证部分，不要求用户在聊天中发送 Token。

**实施记录（2026-10-22）：** 代码已实现并安装，16 项测试、类型检查及两轴审查通过。用户确认设置页保存成功；真实 daemon RPC 在重载前后均返回 connected，字段类型通过契约验证。用户选择暂不检查深浅主题及手机窄屏，因此第一项保留未勾选，任务尚未完成全部验收。详见 [验证记录](../../../docs/connection-validation.md)。未推送。

# 02: 全局 MR 看板与历史查询

**What to build:** 当前用户可跨仓库查看“我创建”和“我参与评审”的 MR，查询开放及历史状态，手动刷新和继续加载结果。

**Blocked by:** 01 — 连接工蜂账号。

**Status:** ready-for-human

**规格依据：** [首期实施规格](../spec.md)，用户故事 13–17。沿用任务 01 的身份和连接处理；按关联仓库筛选在任务 08 结合任务 03 交付，本任务的全局查询不依赖关联记录。

- [x] 看板提供“我创建”“我参与评审”两类关系，后者包含已审查事项，不标记为精确“待我处理”。
- [x] 支持开放、已合入、已关闭、全部状态；开放结果包含重新打开的 MR，未知状态保留可辨识信息，不无提示丢弃。
- [x] 核对实际 dashboard 响应的分组、用户过滤、状态参数和分页语义；不用其他端点或 MCP 的字段推测契约。
- [x] 两类关系分别维护分页、加载和错误状态；按工蜂仓库与 MR 身份去重，稳定展示仓库、编号、标题、状态及原站入口。
- [x] 支持手动刷新和继续加载；未加载的后续页不冒充全量，切换账号或过滤条件后不会混入旧结果。
- [x] 空结果、认证失败、项目无权访问、限流及暂时性服务失败有区分；一个请求失败保留其他成功数据，重试有界。
- [x] 业务 RPC 集成测试覆盖分组响应、重复项、分页边界、历史及 reopened 状态、401/403/404/429、非 JSON 和服务异常。
- [ ] 完成类型检查、实际宽屏及紧凑看板操作；用安全配置的账号抽样核对真实列表和历史状态，不保存私有正文。

**执行边界：** 不实现提及看板，不全量扫描评论推断待办，不引入后台磁盘索引或远程写操作。保持全局发现未关联仓库的能力。

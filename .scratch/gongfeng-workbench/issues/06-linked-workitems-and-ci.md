# 06: TAPD 关联与 CI 摘要

**What to build:** 用户在 MR 详情中看到已经绑定的 TAPD 工作项链接、对应提交的 CI 检查摘要及原站入口，权限不足时仍可使用其他详情。

**Blocked by:** 05 — MR 详情与审查上下文。

**Status:** ready-for-human

**规格依据：** [首期实施规格](../spec.md)，用户故事 19–21。消费任务 05 的 MR 身份、版本及详情布局，沿用已有局部加载与错误行为。

- [x] 通过工蜂 OpenAPI 获取 MR 已绑定的 TAPD 工作项，使用经核验的原站链接；区分未绑定、无权限和读取失败。
- [x] 查询与所展示 MR 提交相对应的 CI 检查摘要，呈现检查状态和原站链接；不得把其他分支或旧提交的结果显示为该版本验证通过。
- [x] 处理 CI 摘要的分页或未完整加载状态；没有足够信息时标记未知，不把空检查列表等同通过。
- [ ] 核验实际最小权限和响应结构；CI 要求更高权限时明确提示，不自动申请或扩大权限。
- [x] TAPD 或 CI 任一接口失败不会清空描述、差异和讨论；原站跳转不携带工蜂 Token，不将外链当作可任意抓取的 API。
- [x] 业务 RPC 集成测试覆盖无绑定、无权限、部分失败、检查为空、多个检查、版本不一致及分页；固定数据不含真实私有内容。
- [ ] 完成类型检查、详情区块的深浅主题及紧凑布局检查；记录真实只读抽样中可验证的权限和数据行为，无权项如实标记。

**执行边界：** 本项目的任务管理仍只使用本地 Markdown，不创建或同步 TAPD 任务。产品只展示 MR 已有 TAPD 链接和 CI 摘要，不实现完整需求系统、流水线任务/日志或触发操作；不会成为 Review 派发的前置依赖。

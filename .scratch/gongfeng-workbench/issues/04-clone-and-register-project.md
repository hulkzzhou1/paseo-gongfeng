# 04: 克隆仓库并创建项目

**What to build:** 用户从工蜂仓库选择本地目标位置，完成 clone、Paseo 项目登记和仓库关联；中途失败时知道已完成步骤，并能安全恢复。

**Blocked by:** 03 — 仓库与已有项目关联。

**Status:** ready-for-human

克隆和登记功能已实现，集成验收状态见对应验证记录。

**规格依据：** [首期实施规格](../spec.md)，用户故事 7、11。复用任务 03 的仓库选择和关系保存；本任务验证项目登记接入方式，不假定插件 SDK 存在 projects.create。

- [x] 先验证当前 0.12 中可用的插件侧项目登记途径，确认操作作用于用户选中的 daemon；记录实际入口和版本，不能使用未发布或仅底层客户端具备的方法冒充插件 API。
- [x] 仓库管理提供克隆并创建项目的完整入口，展示目标位置、过程状态和最终项目；成功后建立任务 03 定义的关系并可在宿主中找到项目。
- [x] 使用可信的目标仓库地址及现有可用 Git 认证；不把 OpenAPI Token 验证通过等同 Git 认证通过，不将秘密放入 clone URL、进程参数、日志或 remote。
- [x] 目标目录已存在或不适宜克隆时给出可操作错误，不覆盖已有目录，不修改用户的现有工作区；输入作为数据传递，不拼接执行 shell 指令。
- [x] 分别处理 clone、项目登记和关联保存失败，显示已创建资源及当前进度；重试前核对资源，避免重复项目和重复关联，不用删除用户目录作为恢复手段。
- [x] 临时真实 Git 仓库验证 clone 成功、目标冲突和中断；受控宿主响应验证登记失败、保存失败及重试恢复。
- [x] 完成类型检查与实际宿主最小流程验证：选仓库、clone、登记、关联、在项目列表可见。若宿主途径不可行，报告具体证据与影响，不将功能默默删除或算作通过。

**执行边界：** clone 是本地获取代码，不创建远程仓库，不推送，不改变已有项目代码。Git 权限和项目登记是本任务的技术前置验证；失败不阻塞已有项目关联及其 Review 路径继续使用。

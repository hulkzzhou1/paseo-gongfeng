# 工蜂插件 MCP 适配

Status: ready-for-human

## 范围与架构

用户授权将当前适合 Agent 使用的工蜂业务能力注册为插件 MCP 服务。配置页新增持久化MCP开关，默认关闭；开启才注册，关闭撤销注册并停止服务。开关为当前host级设置，配置未就绪时不提供可调用服务。UI 保持 RPC；两种入口调用同一批内部业务处理函数、凭据层和队列，不反射或自动导出 RPC。不新增 daemon MCP 代理、不注入系统提示词或工蜂 Token 环境变量。

采用插件进程内的多客户端 Streamable HTTP 服务：绑定 loopback，随机端口及临时认证；标准 MCP SDK 负责协议。这样 UI／MCP 复用同一个业务实例和本地写队列，不产生 stdio 子进程并发覆盖本地存储的问题。只通过 registerMcpServer 注册定义给 provider，新会话自然获取。服务注册、撤销和监听端口由插件生命周期管理。

明确列出工具：连接状态（不修改凭据）、已添加／搜索／添加仓库、项目关联查询／保存／解除、克隆与克隆记录、MR 列表／详情／差异／讨论／审查／评审人搜索与保存／提交意见／TAPD／CI、里程碑查询／管理／关联。凭据配置、UI 路由和宿主运行时不导出。写工具要求显式 confirm:true；原有版本、身份、归属、权限和部分结果约束继续有效。

## 验证

首个切片为 MCP 列出已添加仓库并与 RPC 比较。实现阶段的自动化使用隔离 daemon、临时数据、虚构 HTTP 边界，不访问生产数据、不进行真实工蜂写入、不调用模型。验证工具发现、输入输出、读写标记、未知工具、错误脱敏、注册更新／撤销、旧连接拒绝、项目隔离及共享队列。仅运行相关套件和类型检查，不跑全套（本次用户明确要求）。

## 交付边界

依赖并核实 fork beta.901 的 registerMcpServer／pluginMcpServers 能力；不假定官方 npm 同版本具有接口。代码、工具矩阵、验证命令与退出码、生产接入步骤保存在项目。实现阶段未改生产配置；后续本机接入另经用户授权。始终不重启生产 daemon或已有Agent、不发布社区。

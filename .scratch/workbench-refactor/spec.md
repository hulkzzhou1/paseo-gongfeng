# 工蜂工作台重构

**Status:** ready-for-human

## Problem Statement
各业务页面的布局和加载体验不统一，切页可能重复取数，MR 概览会请求未打开的差异和讨论，刷新可能打断阅读及编辑。

## Solution
参考 TAPD 的紧凑界面，统一工蜂工作台与查询策略，保留现有业务、数据、MCP 和权限语义。

## User Stories
1. 使用者可在 MR、议题、里程碑和仓库管理之间切换，保留筛选及加载结果。
2. 桌面使用者通过紧凑表格识别标题、仓库、状态、人员及时间。
3. 手机使用者通过紧凑列表浏览相同信息，无整页横向溢出。
4. 使用者通过右上角设置弹窗配置连接及刷新周期。
5. 使用者打开悬浮抽屉查看详情，底层页面不被挤压。
6. 使用者在 MR 概览无需等待差异和讨论取数。
7. 使用者查看简短描述，按需打开完整富文本。
8. 使用者在新鲜期内返回页面时复用数据。
9. 使用者可选择关闭、30、60、120、300 秒自动刷新，默认关闭。
10. 使用者进入后台时停止周期刷新，返回时过期再更新。
11. 使用者首次加载见中央旋转提示，后续更新保留已显示内容。
12. 使用者在刷新失败时看到错误及上次成功时间。
13. 使用者手动刷新回到第一页并重新读取远端。
14. 使用者加载多页后自动刷新暂停，有明确提示。
15. 使用者编辑时保留草稿，离开前确认继续或放弃。
16. 使用者切换站点或账号后不再看到旧身份的数据与草稿。
17. 使用者写入后及时看到受影响列表、详情与关联资源更新。
18. Agent 继续通过原有 MCP 工具管理工蜂，工具及注入边界不受 UI 重构影响。

## Implementation Decisions
- 列表新鲜期30秒，详情60秒，候选信息10分钟；稳定业务查询身份，不以请求时间戳建新查询。
- 只刷新当前可见模块；页面后台及多页加载后暂停周期刷新。缓存内返回不做无用重拉。
- 共用工作台外壳、列表列布局和加载状态，保留既有抽屉动画、焦点管理和宿主表单。
- 保留服务端版本复核、只写一次、结果回读与不确定结果保护。首先不增加服务端缓存。
- 首次按需加载重成本区域；已访问区域可缓存，但隐藏区域不周期刷新。
- 刷新不替换正在编辑的初始值；关闭编辑、详情、切换模块均保护草稿，身份变化直接清除。
- 按当前宿主保存刷新设置。列表筛选与浏览位置仅在当前客户端会话内保留，缓存不持久化私密正文。

## Testing Decisions
用户Q9已确认前端查询＋受控RPC／时间／可见性、共享RPC／标准MCP、真实UI边界。
- 用真实 QueryClient/Observer 与受控请求验证请求计数、新鲜期、暂停／恢复、分页与精准失效。
- 复用现有业务测试验证权限、版本冲突、写入不自动重试和MCP兼容，只为受影响行为补回归。
- 真实UI检查桌面、手机窄屏Web、深浅主题、键盘、抽屉、草稿离开确认；真实工蜂只读，不调用模型。
- 新鲜期内切回同一条件无业务列表重拉；MR概览无差异／讨论请求；后台无周期请求；多页暂停；手动回第一页。

## Out of Scope

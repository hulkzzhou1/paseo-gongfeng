# 工蜂议题模块

Status: ready-for-human

## Problem Statement

用户目前只能在里程碑中看到关联议题摘要，必须返回工蜂原站管理议题、人员与评论。希望在同一插件完成日常管理，并让已关联项目中的 Agent 通过 MCP 使用相同能力。

## Solution

增加顶部“议题”入口、紧凑跨仓列表与悬浮详情抽屉，默认汇总已添加仓库。提供完整详情、新建、编辑、状态、人员／分类、评论操作，同步暴露明确 MCP 工具；数据直接来自当前站点 OpenAPI。缺少正式删除契约时明确保留能力缺口，不提供不可用按钮或猜测请求。

## User Stories

1. 作为用户，我希望汇总所有已添加仓库的议题，不以项目是否本地关联为读取条件。
2. 作为用户，我希望筛选单仓库、全部／我创建／指派给我，看到别人创建的可见议题。
3. 作为用户，我希望默认查看开放议题，并切换已关闭和全部，按最近更新排列。
4. 作为用户，我希望搜索关键词或仓库内编号，并知道搜索实际覆盖范围。
5. 作为用户，我希望逐步加载跨仓结果，区分未加载、空集合和无权限仓库。
6. 作为用户，我希望点击议题打开悬浮抽屉，不挤压列表。
7. 作为用户，我希望看到作者、处理人、优先级、标签、里程碑、私密与解决状态。
8. 作为用户，我希望描述和评论正确显示标题、代码、表格、链接和只读任务清单。
9. 作为用户，我希望从里程碑关联议题直接打开议题详情。
10. 作为用户，我希望新建默认普通的议题，填写标题和描述。
11. 作为用户，我希望编辑已读取的议题，避免覆盖更新后的版本。
12. 作为用户，我希望关闭／重开同一个议题，并确认实际结果。
13. 作为用户，我希望私密议题显著标注，编辑保留属性，改为普通时单独确认。
14. 作为用户，我希望多选至多十位处理人，修改或清空指派。
15. 作为用户，我希望设置优先级和独立解决状态，不混同于议题开放／关闭。
16. 作为用户，我希望从当前仓库已有标签中选择、替换或清空标签。
17. 作为用户，我希望关联同仓里程碑或取消关联，不混淆标题与全局身份。
18. 作为用户，我希望分页阅读、发表评论，并编辑自己的非系统评论。
19. 作为用户，我希望其他人和系统评论保持只读，不显示虚假的编辑权限。
20. 作为用户，我希望知道 fork 关联议题的状态和评论可能由工蜂同步到其他仓库。
21. 作为 Agent 调用方，我希望 UI 和 MCP 共用账号、仓库、字段和写入语义。
22. 作为用户，我希望未知结果不自动重发，权限失败不被当作空集合或保留其他账号的私密缓存。
23. 作为用户，我希望知道删除是否真的受支持；没有正式契约时保留明确缺口。
24. 作为用户，我希望桌面与窄屏都能操作，编辑弹窗有足够描述空间。

## Implementation Decisions

- 复用当前站点会话、已添加仓库边界、业务 RPC 执行器、标准 MCP 显式 allowlist 和写队列，不新增通用远程 API 代理。
- 仓库查询逐仓使用项目议题列表，最多四仓并发，每仓保留游标；不将“用户创建议题列表”冒充全部。关键词搜索以部署接口实际能力为准，说明已加载与剩余范围。
- 身份包含站点、当前账号、工蜂仓库和全局议题 ID；IID 用于展示与明确的编号查找。版本摘要覆盖完整可编辑数据，提交前复核，写后回读；不宣称平台提供原子条件写入。
- 共享严格输入输出契约，字段白名单逐项扩展；未指定字段不修改。清空正文、人员、标签、里程碑的请求编码须经专用样本验证。
- 人员使用当前仓库权限成员候选，标签使用已有标签，里程碑限定同仓。候选均分页，不因为上游未知字段伪造可编辑值。
- 普通／私密切换在 UI 与 MCP 一致约束，私密改普通需要独立确认参数／界面确认。
- 评论分页展示；仅允许编辑当前账号的非系统评论，编辑前复核评论版本和作者，处理未知结果且不重试写入。
- 已知 fork 关联状态和评论同步只提示平台行为，不自行同步／重发。
- 沿用紧凑按钮、主题色、富文本、放大表单与悬浮抽屉。新增与里程碑之间的导航和缓存刷新，不修改 MCP 项目注入边界。
- 继续寻找正式删除契约；未取得前不实现议题／评论 DELETE，不把缺口标为完成。

## Testing Decisions

- 用户已确认共享 RPC、标准 MCP 发现／调用、真实 UI 与专用 e2e 三层边界。
- 通过公开业务调用与受控 HTTP 验证隔离、分页、字段、权限、旧版本、私密确认、评论作者、无自动写重试与回读，不测试私有函数实现。
- 标准 MCP 验证发现、输入与确认守卫、结果等同 RPC；无需模型，不以工具清单代替调用成功。
- 真实验收仅在专用 e2e 仓库创建带前缀虚构议题／评论，只改本轮样本。测试字段设置／清空与关闭／重开，结束关闭样本；删除无契约时允许保留评论历史。
- 界面验证桌面／窄屏的详情、表单、取消、确认和富文本；未测原生端不声称通过。
- 正式双轴审查固定基准 9fef47c；针对性测试随切片运行，末尾统一检查。

## Out of Scope

- 回复线程、附件上传、修改其他人或系统评论，仓库标签的创建／删除。
- fork、订阅／置顶／导出、TAPD 接入、Agent 派发、扩大 MCP 注入范围。
- 猜测删除接口、无正式契约的真实删除试探，真实业务议题／评论写入，模型调用。
- 本轮社区发布或替换安装来源。

## Further Notes

用户已确认整体范围、五项拆分及验证方式。接口差异与原始证据见设计及调研记录；删除、原生端与不同部署版本的限制需如实交付。

实现与已执行的验收见 [议题验证](../../docs/issues-validation.md)；删除无正式契约，保留明确缺口，不标为删除已实现。等待用户验收，未发布新版。

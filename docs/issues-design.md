# 议题模块设计讨论

日期：2026-10-26。用户要求将工蜂议题能力接入插件。整体范围、五项拆分、三层验证及 9fef47c 审查基准均已确认，已完成本地实现与验收，等待用户复核。规格见 ../.scratch/gongfeng-issues/spec.md，本轮不发布。

## 实施前核对的现状

- 插件直接调用工蜂 OpenAPI，服务端保存站点凭据。UI RPC 与 MCP 复用业务处理；议题模块沿用此路径，不转接内部远程 MCP。
- 当前只有里程碑中的关联议题摘要、分页候选、查看原站及里程碑关联写入，没有独立议题列表、完整详情、正文编辑或评论模块。
- 已添加仓库与本地项目关联是两层关系；查看仓库议题不应要求仓库已关联本地项目。现有 MCP 只向有效关联工蜂仓库的项目中新建 Agent 注入，不因新增议题工具自动扩大该边界。
- 描述／讨论已有共用安全富文本渲染、纯文本摘要、表格和只读任务清单，应复用；不直接执行工蜂返回的 HTML。
- 本项目规格与任务使用本地 Markdown，不接入 TAPD。新模块不恢复 MR 中的 Agent Review 派发，也不意味着自动将议题派发给 Agent。

## 第一轮已确认

1. **完整管理，包含删除目标**。第二轮进一步确认：若始终无法取得正式删除契约，允许先交付其他能力并明确保留缺口，不展示无效按钮、不调用猜测接口。
2. **默认汇总已添加仓库，可筛选单仓库**；提供状态、关键词以及全部／我创建／指派给我的关系筛选。不同仓库同 IID 必须区分，不使用用户创建列表替代全部。
3. **顶部独立议题入口、紧凑列表和悬浮详情抽屉，界面与 MCP 同时支持**，共用业务逻辑及权限检查。

“完整管理”不是对外围所有功能的自动批准；后续字段与评论范围以下方确认记录为准。

## 第二轮已确认

- **全部编辑字段纳入**：标题、描述、多处理人、优先级、已有标签、同仓里程碑、私密标记，以及独立于开放／关闭的解决状态。不包含创建／删除仓库标签。
- **评论支持查看、发表、编辑自己的非系统评论**。他人评论与系统评论只读，不纳入回复线程或附件上传。议题及评论删除继续寻找正式契约；无契约时明确保留能力缺口。
- **允许带明确删除缺口交付其余能力**。不提供无效删除按钮、不使用猜测接口、不将其标成已完成；没有正式契约前不试探真实 DELETE 请求。

## 第三轮已确认

- **默认开放、按最近更新排列**，支持已关闭／全部、全部／我创建／指派给我，以及仓库／关键词筛选。跨仓逐步加载，未查仓库、分页与局部失败明确，搜索范围按 API 实测说明。
- **新建默认普通、私密改普通单独确认**。读取遵守当前 Token 权限，私密标记显著；编辑保留原属性，不因权限错误展示旧账号缓存。MCP 沿用服务器账号权限及显式写入确认约定。
- **允许专用 e2e 样本真实验收**：仅创建带测试前缀的虚构议题／评论，验证字段设置、清空、关闭与重开；只改本轮自建样本，不调用模型。不试探无契约的删除；最后关闭样本，允许保留测试评论历史。

## 实施切片（已确认）

每项均贯穿业务契约、OpenAPI、UI、MCP 与针对性测试，不单独拆出大框架或通用 API 代理。

1. **查询与详情**。无前置；独立入口、跨仓筛选／分页／失败提示、完整详情和格式化描述，UI／MCP 均可读取；里程碑关联议题可进入详情。
2. **新建、编辑与状态**。依赖 1；标题／描述／私密属性、创建与编辑表单、关闭／重开、私密改普通确认，UI／MCP 共用版本复核和写后回读。
3. **人员与分类信息**。依赖 2；多处理人、优先级、已有标签、同仓里程碑、独立解决状态的查看／编辑／清空；验证候选范围、字段编码及部分／未知结果。
4. **议题评论**。依赖 1；分页读取、格式化正文、发表及编辑本人非系统评论，UI／MCP 同步；已知 fork 关联同步提示，不自行扩展回复／附件。
5. **集成与交付验收**。依赖 2、3、4；三处入口状态与缓存一致、只读／写入权限、三层验证、专用 e2e 样本清理、双轴审查，以及删除契约缺口与实际覆盖说明。

## 验证边界（已确认）

- **共享业务 RPC**：受控 HTTP 和临时数据验证仓库／账号隔离、字段与参数、分页、旧版本、权限失败、不自动重试写入及回读。无法单独证明真实工蜂部署接受参数。
- **标准 MCP 发现／调用**：验证新增工具可发现、输入校验／写入确认、结果与 RPC 一致及原有工具不回归。无需真实模型；不把工具清单可见当作连接调用成功。
- **真实 UI 与专用 e2e**：验证桌面／窄屏的浮层、编辑草稿、取消、确认，以及已授权样本的字段实际设置／清空和生命周期。测试历史仅留在专用仓库；不操作既有业务议题，不对未测原生端作通过声明。

正式审查固定基准为用户选择的 `9fef47c`，将此前里程碑修复排除；当前调研／设计文档与本轮范围一同纳入审查。

## 事实核验

官方接口研究已完成首轮核查，见 [接口研究](issues-research.md)。区分 HTML 与 Swagger 的遗漏、文档承诺与真实部署行为，避免将“我创建的议题”接口误当成全部议题。调研未读取凭据或执行真实议题写入。

初步核对：`GET /issues` 明确为用户创建的议题；项目议题列表的关键词／作者／处理人等参数在官方 Swagger 中有补充。`GET /dashboard/issues` 存在，但其默认关系集合仍需验证。HTML 与 Swagger 均未发现议题及其评论的 DELETE 接口；不能将产品“完整管理”的目标直接当成接口已支持的事实。人员参数在两份文档中的编码有差异，需隔离联调，不应套用 GitLab 字段约定。

官方产品说明明确 fork 关联议题的评论与状态变化会双向同步。因此操作可能影响关联仓库，插件应展示已知关联与平台同步提示，不承诺单仓无副作用，也不自行重发请求同步其他仓库。

## 本地实现结果

五项切片已完成，任务标记为 ready-for-human。最终验证和保留限制见 [议题验收](issues-validation.md)。未发布新版；删除能力因缺少正式契约保持明确缺口。

## 公开资料能确认的事实

- [工蜂多版本介绍](https://code.tencent.com/help/game/multiVersion/)列出公网 SaaS git.code.tencent.com，面向内外部用户自助注册。
- [API 使用说明](https://code.tencent.com/help/api/prepare)列出 /api/v3、认证和分页等基础机制；[OAuth2 文档](https://code.tencent.com/help/oauth2/)列出用户查询。
- [代码评审文档](https://code.tencent.com/help/productionDoc/codeReview)说明产品有 MR 差异、评论等能力，但不能据此断言内外网 REST 契约相同。
- 公网项目查询参数、dashboard MR、MR 详情及差异和讨论响应、CI 摘要、TAPD 关联尚待公网账号实测。未找到明确契约不代表接口不存在。
- 本轮版本介绍和 API 说明主要来自官方搜索索引，直接打开超时；未使用内部 Token 访问公网实例。

## 已确认的范围决策

用户已同意首轮三项建议：

1. 产品范围：先前讨论内部工蜂与公网 SaaS；用户最新确认改为自定义工蜂 HTTPS 站点根地址。接口要求兼容本插件使用的 OpenAPI v3，不能仅凭地址可填写就宣称所有版本可用。
2. GitHub 导入：审阅代码、测试和公开文档后建立干净初始提交，内部历史继续保留在 origin。
3. 许可证：自有代码采用 MIT；第三方代码保留其所需许可证与署名。

MIT 许可证现已添加。公开版本使用干净初始提交，不带入内部历史、验收材料和运行数据；具体公开状态以任务 11 的结果为准。

第二轮用户已同意，并补充以内部工蜂支持为主：

4. 实例连接：每个实例保存一个账号，每次只查看及操作一个实例；切换保留另一实例的连接、关联和历史，数据按实例隔离。已有安装自动归入内部实例，原有数据不丢失。
5. 仓库维护：干净导入后以 GitHub 为开发主仓库，内部旧仓库保留历史，首期不建设双向同步。
6. 公网能力：仓库关联、MR 看板与详情、Review 派发是公网首期核心；TAPD 与 CI 按实际支持和权限显示。核心链路未实测通过前不宣称公网可用，可选能力不可用时明确提示，不阻断基础审查。

内部工蜂是主要使用场景与回归基准；公网适配不能降低内部版本的能力或阻塞内部交付。

## 当前界面改版

用户已要求直接参考 GitHub 工作台的页面组织，提高 MR 管理界面、工蜂设置页的信息密度，优化代码差异展示；工作台右上角设置按钮在弹窗内打开同一份工蜂配置。

本轮实现沿用 React Native、Paseo 0.12 原生组件和主题：紧凑列表、关系与状态筛选、集中操作栏；详情按概览／文件变更／讨论／Review 分区；差异使用等宽字体、增删语义色、行号、文件折叠和横向滚动。保持现有账号核对、分页、版本核验及派发流程，不修改工蜂写权限。

用户随后明确的交互要求：

- MR 详情在右侧悬浮抽屉打开，覆盖列表而不挤压其宽度；有遮罩与滑入/滑出动画，遵循减少动态效果设置。关闭保留原列表及筛选；窄屏占满可用宽度。
- 描述默认仅展示前 120 个 Unicode 字符的摘要，合并空白；全文在最高 1040px 的弹窗内分段展示，窄屏保留边距，支持标题、列表、引用、代码与安全网页链接。服务端截断时明确提示。
- “仓库关联”入口改为“仓库管理”，首页仅展示已添加仓库。添加弹窗使用一个组合下拉控件，展开后在面板顶部搜索，选中后收起；不在首页枚举全部可访问仓库。
- 每条仓库通过“关联项目”弹窗选择具体项目。保留已有克隆与关联恢复能力；旧关联自动出现在列表中，解除关联保留已添加仓库。
- 视觉优先突出 MR 标题与选中项，弱化刷新等辅助动作，默认折叠 SHA 与读取时间。TAPD 使用明确标识、强调边线和独立工作项卡片，与 CI 检查列表区分。
- MR 列表显示所有者的英文账号 `author.username`，缺失时明确标为未知，不替换成显示名或当前评审人。

本轮交付与验证见 [界面改版任务](../.scratch/gongfeng-workbench/issues/10-workbench-redesign.md)。

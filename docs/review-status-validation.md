# 审查状态卡片与统一刷新验证

日期：2026-10-22。基于本轮开始版本 `d28c172`；Paseo daemon／Web UI 0.12.0。只读 OpenAPI 和本地临时测试，不调用模型，不改变远程评审状态。

## 行为

- 概览优先显示代码评审卡片：中文总体状态、评审人数、首字母标识和个人状态图标、同意人数；可展开姓名／英文账号、必要评审人标签和个人结论。
- 展示普通及必要评审规则；总体状态保留工蜂返回值，不从 MR 已合入或同意人数推导。缺失／异常规则、未知人员类型保留待核对提示；无评审人不冒充全部通过。
- 现有 API 未提供可靠的讨论解决门禁汇总，卡片仅提供原站核对入口，不把已加载评论数当作未解决数。
- 详情右上角只保留一个刷新按钮，更新描述、差异、讨论、评审、TAPD、CI 和 Review 历史。局部失败保留独立错误，不清空其他区块；刷新不准备或派发 Review。
- 新字段允许缺失，旧版持久化 Review 快照可继续读取及恢复。原历史版本和资源身份保持不变。

## 证据

- 业务 RPC 回归先红后绿：新增规则和人员类型透传；缺失及异常可选字段降级；模拟旧版磁盘记录，重载后通过 history／prepare 恢复同一操作，没有工作区或 Agent 创建。
- 真实只读样本：接口包含 `approver_rule`、`necessary_approver_rule`、`reviewers[].type`；客户端样本显示 3 位评审人、0 位同意，与展开后的 3 个英文账号和个人状态一致。无需必要评审人同意的规则独立展示，不受人员名单中含必要评审人影响。
- 一次真实点击右上角刷新，临时只记录 WebSocket 发出的 RPC 名称，确认 `mr.detail`、`mr.changes`、`mr.review`、`mr.notes`、`mr.tapd`、`mr.ci`、`review.history` 均重取，未发出 `review.start`；计数器随后撤销。没有采集请求正文、凭据或业务内容。
- Web 1280×800：卡片宽 631px。390×844：抽屉宽 390px、卡片 x=13／宽365；展开人员后仍在视口内，页面无横向溢出。每个详情仅一个刷新按钮，区块刷新按钮为零。
- 实际 Light 和系统暗色主题检查；截图仅截取遮盖页面背景、替换人员文本后的临时卡片副本，检查后移除；没有保存私有 MR 截图。恢复原“系统”主题和 1280×800 视口。

最终统一检查见本轮执行结果：TypeScript、134 项自动化和 `git diff --check`。插件重载为 running。

## 契约依据与边界

规则值依据官方工蜂文档：`-1` 全部、`1` 单人、`2+` 指定人数，必要规则 `0` 无需必要评审人同意。人员与规则随 MR Review 响应读取，不拿项目当前配置替换历史 MR 规则。

- [MR Review API](https://git.woa.com/help/menu/api/cr/mr_review.html)
- [分支规则字段](https://git.woa.com/help/menu/api/branches.html)
- [评审人及规则说明](https://code.tencent.com/help/productionDoc/codeReview)
- [评审拒绝状态示例](https://code.tencent.com/help/webhooks)

公网账号验收按用户选择暂缓；窄屏浏览器不是原生 iOS／Android 验收。真实权限故障、所有键盘／屏幕阅读器路径、所有外部状态组合尚未穷举。

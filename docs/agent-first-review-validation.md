# Agent 自行准备 MR Review

> 历史记录：2026-10-23 用户决定移除 MR 内 Agent Review 派发。当前卡片、派发及历史恢复 RPC 和专属实现已删除；已有 Agent、工作区和历史文件保留，已有 Agent 通过 Paseo 原有入口访问。下文仅保留此前阶段证据。


日期：2026-10-23。用户已明确选择先启动 Agent，并指出已有关联项目可直接创建 worktree。该选择替代旧的“先准备 diff／固定版本完整仓库再派发”默认流程。

## 新流程

- 点击发起 Review，只读取有效关联与预设、基本 MR 身份及源目标 Git 线索；不读取 changes、notes 或 review。单一项目直接显示项目名称，多关联时保留选择。
- 选择预设、填写要求后，调用当前0.12 SDK 创建该项目的新 worktree，再创建 Agent，成功后直接打开 Agent。没有前置 MR fetch、完整检出、子模块／LFS 扫描或大段差异快照。
- worktree 从关联项目当前本地提交创建。0.12 宿主不接受 `baseBranch=HEAD`，因此仅在本地解析 HEAD 为提交号并传给宿主，不使用远程跟踪分支触发宿主的远程刷新。
- 任务以 MR 链接、仓库/IID、用户要求为主，带基本源目标 SSH 地址和分支，支持 fork。由 Agent 自行获取 MR 内容、fetch／切换代码并记录实际源、目标与比较基准 SHA；初始 worktree 不能冒充 MR 版本。
- 插件仍直接使用 OpenAPI，不新增工蜂 MCP、凭据转发、HR 或额外本地网络服务。目前的 UI 只读 RPC 不是通用 Agent 工具；此轮采用用户允许的 Git/worktree 路径，任务也允许使用运行环境本已有的只读能力。
- 预设完整运行参数仍在服务端冻结，Token 不进入任务或 Git remote。仅当前新 worktree 中审查，允许 fetch／检出与相关本地检查，不自动修改业务代码或执行远程写操作。
- 历史 full/diff 的原快照及显式恢复继续兼容；原 RPC 的未指定模式保留旧语义以兼容调用方，新界面明确使用 agent 模式。并发、重载、失败和未知 prompt 结果仍复用同一次 operation，避免重复创建或重发。

## 自动化

现有业务 RPC 与临时真实 Git 边界增加5项回归：轻量准备不预读正文、diff、讨论或评审；创建正确项目的真实 worktree、插件不 fetch、不传大段快照或凭据；失败／并发／重载复用且不受 Agent 后续分支或本地产物影响；任务结果未知不重发，项目／预设变化仍拒绝。旧完整模式、仅 diff、历史与账号／站点隔离回归保留。统一检查173项通过，含旧快照不能伪装为新模式启动的防混用回归。

## 真实验收

服务器浏览器已验证单一关联不再要求重选项目、固定 SHA 大表单和 diff 降级入口不出现在新派发中；测试选择现有“工蜂验收”预设，确认 codex/gpt-6-luna、low 后仅启动一次短任务。点击启动至自动打开 Agent 约2785ms，为本次样本观测，不是性能保证；独立worktree归属及目录正确，原项目目录状态未变。

该低成本预设使用auto模式（workspace-write），默认网络关闭。首次Git只读请求失败，宿主同目录SSH成功；同一Agent按现有审批机制申请单次有界Git操作后完成fetch／检出和merge-base核对，未修改预设或提高模式权限，未创建第二个Agent。验收产物的源、目标和基准三个SHA均实际存在，HEAD等于源SHA，git merge-base结果等于记录的基准SHA。Agent idle，模型仍为gpt-6-luna；测试只做身份和版本核验，没有完整业务代码审查或仓库测试。任务补充了受限模式使用原有审批、未获许可明确报告限制的说明。

原生手机、其他provider和公网账号仍待验收。新模式的实际代码读取依赖所选Agent运行模式的网络／SSH权限；这不是插件已预检出或保证所有预设均能直接联网。

# 评审人分组与头像验证

日期：2026-10-23。运行环境：Paseo daemon／Web UI 0.12.0。沿用统一卡片与服务端人员保存契约，没有调用模型或向真实 MR 保存人员／意见。

## 本次实现

后续尺寸修正：Web 评审人弹窗宽度上限720px、高度上限560px，并受视口留白约束，覆盖宿主 bounded modal 的85%高度。1440×1100大屏实测720×560，保存按钮可见；悬浮候选仍在弹窗内且不移动按钮。新增限定当前弹窗及卸载恢复宿主尺寸的回归，统一检查164项通过。

- 卡片以紧凑头像栏展示评审人，必要人员有星形标识，右下角显示真实意见状态；展开显示姓名、英文账号、类型和状态。编辑入口放在卡片底部，当前账号是评审人时才保留意见按钮。
- 普通与必要评审人分组，已选人员显示为带头像的可移除标签。展开为悬浮下拉，在下拉内部搜索项目成员，勾选后保持展开，允许连续多选；下拉覆盖表单而不占布局高度，底部空间不足时向上展开，搜索／分页在其内部滚动；另一组已有成员可移入当前组，人员不重复。未知类型不可默认为普通角色，100 人上限仍允许移除和调整已知角色。
- 规则只读显示。进度分母使用实际通过门槛；全部同意时使用人数，缺失／零人／未知类型不伪造通过。讨论门槛仍提示在工蜂核对。
- `avatar_url` 映射到可选展示字段，接受 HTTPS、站点相对路径和本站无协议地址；丢弃带账号、查询或片段及非 HTTPS 地址。头像由客户端加载，不携带 Private Token，不使用服务端图片代理；失败回退为首字母，旧历史没有头像字段仍兼容。头像变化不改变名单版本。
- 真实样本的评审、项目成员以及官方单用户资料接口都返回默认头像。用户明确接受 OpenAPI 返回的信息，不接入内部 HR 或其他人员服务。此次没有保留额外用户资料 API 路径、查询功能或凭据。
- 保存仍需显式点击，保留版本冲突、权限拒绝、部分成功与结果未知提示，写请求不自动重试；取消／Escape 关闭整个弹窗不写入。

## 验证

- `npm run check`：本地任务状态、TypeScript 和163项测试通过。服务器浏览器检查1120×720深色与390×844浅色，无横向溢出；展开后保存按钮位置与表单高度不变，向上展开与连续选择后锚点保持。
- 先以失败测试确认选择器缺失，再覆盖连续添加、取消、类型移动、原数组不变、未知类型、100人限制和悬浮下拉上下避让。头像覆盖 URL 校验、两个业务 RPC 的字段映射、默认与缺失兼容，以及头像变化不影响 revision。
- 服务器浏览器验证真实卡片展开、编辑弹窗分组、当前名单候选、连续添加两人、取消勾选、跨组移动、移除后重选；全程未发出 `reviewers.save`、`review.submit` 或 `review.start`。仅核对头像资源可加载，不把默认图误称为真实照片。

## 限制

真实 MR 的保存和意见写入继续留待人工验收；其权限、部分失败和未知结果证据仍来自模拟 HTTP 的业务 RPC 回归。未验收原生手机与公网账号；用户已明确不要求另接 HR 补充头像。

依据：[官方用户 API](https://git.woa.com/help/menu/api/users.html)、[官方评审 API](https://git.woa.com/help/menu/api/cr/mr_review.html)、[项目成员 API](https://git.woa.com/help/menu/api/projects.html)。记录不包含真实人员名单、业务正文或凭据。

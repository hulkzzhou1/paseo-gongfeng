# 开发检查

这些命令从源码仓库根目录运行，已验证环境为 Linux、Node.js 24 和 Git；没有新增依赖。脚本不随插件运行包交付，也不在安装依赖时自动运行。

## 修改和推送

修改时运行相关测试；收尾运行一次 `npm run check`，依次检查本地规格／任务状态、TypeScript 和全部自动化测试。状态取值来自 [triage-labels.md](triage-labels.md)，检查 `.scratch/*/spec.md` 和 `.scratch/*/issues/*.md` 中唯一的 `Status:` 或 `**Status:**`。缺少标签或任务文件也会失败；状态合法不表示业务验收通过。

每份 clone 执行 `npm run hooks:install` 安装 pre-push。它只写仓库本地 `core.hooksPath`，同仓库 worktree 可能共享该配置，不修改全局配置。已有不同 hooksPath 或默认目录中的活动钩子会保留并拒绝安装；此时把 `npm run check` 手动接入原有 pre-push。重复安装本项目钩子安全。

pre-push 在推送前运行统一检查，失败则阻止推送；它清除 Git 的仓库定位环境变量，防止测试中的临时 Git 操作误指向主仓库。这是本地开发检查，可以被 `--no-verify` 绕过，不替代服务端策略或授权。本任务不会执行真实远端推送。

## 诊断进程

使用 `npm run diagnose:process -- <PID>`。只读取 Linux `/proc/<PID>/stat` 并返回 PID、进程名称和状态；不读取命令行或环境变量，不输出原始异常。进程退出、权限不足、不支持 `/proc` 或参数无效时非零退出。

需要查找 PID 时仅使用 `ps -eo pid,comm,state`。不要采集 `args`、`command`、环境、原始凭据或完整共享配置，也不要复制它们到日志或文档。进程名称由进程控制，元数据白名单不能保证人为写入名称的秘密被隐藏；本工具也不能撤回此前已经输出的内容。

## 真实模型验收

自动化回归不调用模型。确需真实派发时，优先选择现有低成本预设，先核对实际模型，使用短小、有明确结束条件的任务；一次成功即停止。结果未知时先查看历史并复用同一 operationId，不反复创建 Agent。没有合适的低成本预设时先询问，不自动退回昂贵模型。

测试预设不改变产品允许用户逐次选择预设的行为。当前真实验收结论和待验收项只以[集成验收](../integrated-acceptance.md)为准；阶段文档用于追溯证据，不把旧测试数量或旧待办当作最新结果。

# 里程碑模块设计讨论

日期：2026-10-23。状态：用户已确认整体范围，进入规格与实现。

依据：[官方能力调研](milestones-research.md)。沿用当前项目的 OpenAPI 直连、自定义工蜂实例、已添加仓库和仓库关联模型；内部版本优先，保持现有紧凑布局、主题及手机适配约定。

## 已核实的约束

- 里程碑属于工蜂仓库，可关联 Issue 和 MR；身份不能只使用标题。
- 官方文档覆盖列表、详情、关联 Issue 及里程碑增删改查。MR 列表支持按里程碑标题过滤；2026-10-23 补查官方 Swagger 后，确认 MR 更新接受 `milestone_id`，原 HTML 文档漏列该字段。
- 尚未确认官方完成率字段、项目组共享里程碑或跨仓库统一查询接口。详情、分页、权限和日期契约仍需真实只读验证。
- 当前插件没有里程碑字段或页面。本次讨论不恢复 MR 内 Agent Review 派发。

## 第一轮已确认

1. **完整管理，包含删除**：列表、详情、创建、编辑、关闭／重新开启、删除，显示关联 Issue／MR，并在 MR 概览展示里程碑。
2. **默认汇总全部已添加仓库，可筛选单仓库**：不扫描账号下未添加的仓库，不将同名里程碑合并。
3. **顶部独立入口与悬浮抽屉**：入口与“合并请求”并列；紧凑列表与悬浮详情，关联 MR 复用现有详情，Issue 摘要外链。

完整管理的确认表示产品功能范围；不代表允许验收时改动任意真实业务里程碑。

## 第二轮已确认

4. **关联项可添加、移除**：本轮同时支持 Issue 与 MR 的关联编辑，先补充接口验证。不能因未找到接口而静默降级成只读或原站编辑。
5. **进度分别统计**：Issue 已关闭／总数、MR 已合入／总数；MR 已关闭未合入单列。不混成统一完成率；未获取完整数据时明确标记统计范围。
6. **默认活动中、渐进加载**：支持全部／活动中／已关闭、仓库、标题／描述关键词；截止日期优先、无日期置后。跨仓库逐步展示，提示未完成加载及失败仓库，支持加载更多；搜索及排序范围明确为已加载数据，不能冒充全量结果。

## 第三轮已确认

7. **允许确认后迁移**：已有其他里程碑的 Issue／MR 可迁移到当前里程碑；候选显示原里程碑，保存前明确提示将替换原关联。添加、移除先形成草稿，保存才写入。

## 接口验证前置项

- 官方 Swagger：MR 使用 `PUT /api/v3/projects/{id_or_path}/merge_request/{merge_request_id}`，Issue 使用 `PUT /api/v3/projects/{id_or_path}/issues/{issue_id}`，两者均有可选整数 `milestone_id` 查询参数。候选 Issue 列表也有 `search` 参数。依据：https://git.woa.com/api/v3/doc/v2/api-docs。
- 设置关联有官方契约；实施阶段已在隔离样本验证 JSON `milestone_id: null` 取消关联、JSON `due_date: ""` 清空日期，`0` 会被拒绝。逐角色权限和异常场景由业务测试覆盖，未制造真实权限错误。详见[验证记录](milestones-validation.md)。
- 对象归属需在保存前重新读取；如果与形成草稿时不同，提示刷新核对，不覆盖未知的新归属。关联变更不是工蜂提供的事务，部分失败必须展示实际结果。
- 前期调研只读；用户确认整体范围后已进入实现，真实写入限定专用 e2e 隔离样本。

## 交互约定

创建弹窗选择目标仓库并填写标题、描述、可选截止日期；编辑沿用相同表单且不更换所属仓库。删除前明确展示仓库和里程碑名称，再由用户确认。权限不足按实际服务端响应解释，不能把管理失败显示成空数据。

以上表单约定随以下最终方案一起确认。

## 最终方案

- 列表展示仓库、里程碑标题、活动状态、截止日期及逾期提示；描述使用固定长度摘要，完整内容在详情中友好渲染。
- Issue／MR 的列表与统计在打开里程碑详情后按需读取，保留分页与范围说明，不为每个列表行自动扫描全部关联对象。
- 关联候选限定当前里程碑所属仓库，支持关键词与编号查找；允许查看历史状态，不借关联操作关闭、重开、合入或删除 Issue／MR。
- 添加、移除先形成草稿，保存时只提交关联变更；已在其他里程碑下的对象展示原归属，按第三轮决定允许确认后迁移，不静默覆盖。
- 管理表单沿用当前紧凑组件、浮层和主题；新建选择仓库，编辑不更换仓库。默认展示仅当前实例已添加仓库，不跨站点混合数据。
- 删除里程碑必须确认具体仓库与名称，插件不附带删除 Issue／MR 的请求。删除后的关联状态、关闭／重开和编辑日期清空的真实行为均需测试样本回读核实。
- 单次写入不自动重试，失败或结果不确定时刷新核对。权限与局部失败明确显示；取消关联等未验证契约是交付前置条件，不能把未实现按钮作为功能完成。

## 验证与交付

沿用现有业务 RPC 测试入口和 HTTP 边界验证认证、分页、权限、对象身份、只更新指定字段、重复提交、失败及部分成功；不新增真实模型调用。界面复用现有浏览器验收方式，覆盖浅色／深色、桌面／窄屏、悬浮抽屉与草稿取消。

真实接口先验证只读响应；关联取消、日期清空及删除后关系等必须在隔离测试样本验证，未验证的能力不得宣称完成。不以真实业务对象试探写参数，不将模拟测试通过写成真实联调通过。

# 评审操作与统一卡片验证

日期：2026-10-23。延续 `f025eda` 的审查卡片，运行环境为 Node.js 24、Paseo daemon／Web UI 0.12.0。此次没有调用模型，也没有对真实业务 MR 添加、移除评审人或提交意见。

## 行为与边界

- 概览以相同 TAPD 样式展示代码评审、描述、TAPD、CI 和 Agent Review；Agent Review 不再单独占用 tab。文件／讨论分区沿用共用卡片。详情右上角保留一次刷新七类数据的按钮。
- 编辑评审人在弹窗内形成草稿，搜索当前项目及继承成员，支持普通／必要人员的添加、移除和类型调整，保存才写入。候选不等于具备管理权限，最终由工蜂执行权限与必要规则。
- 当前账号不在评审人名单中时，不显示评审按钮及提示，保留编辑人员入口。评审人点击同意后打开意见弹窗，默认同意，可选择需要修改／明确拒绝／评论，附言选填，确认才提交。已同意账号仍可改变意见。
- 弹窗固定打开时的评审版本和源 SHA。服务端复核站点、账号、MR、源 SHA 和评审版本；非评审人不能绕过界面提交。写方法及端点使用白名单，写请求不自动重试。
- 人员调整不是事务。中途失败停止后续步骤、返回实际名单，不自动回滚。意见结果不确定时提示刷新核对，不自动重发。OpenAPI 尚无已验证的原子版本条件，核对与写入之间仍可能发生版本变化。
- 同一人员在 API 中可能同时有普通及必要关系，显示时合并为一个人并保留必要标签，意见冲突标记待核对。版本摘要使用原始关系，不因返回顺序变化而变化。新增字段允许缺失，既有 Review 历史继续可读。

## 已执行

- `npm run check`：本地任务状态、TypeScript、152 项自动化全部通过；`git diff --check` 通过。测试使用临时凭据、模拟 HTTP 和本地临时资源，不读取真实 Token。
- 业务 RPC 集成覆盖项目成员搜索及字段脱敏、普通／必要邀请与移除、类型变化、旧版本拒绝、无变化不写入、部分成功、权限拒绝、未知结果、端点限制，以及四种意见、空附言重复同意、源 SHA 移动及账号／站点隔离。写请求单次执行；旧版磁盘 Review 恢复仍复用原操作。
- 真实浏览器中打开编辑器，搜索、加入草稿、切换类型、移除、取消；取消没有触发 `reviewers.save`。API 重复人员关系归并后，卡片人数与编辑器一致，移除一人只减少一项。未点击保存。
- 对非评审人样本确认按钮和意见提示均不存在，编辑入口保留；对参与评审样本确认按钮可用，弹窗默认仅同意选中，四种选项逐项切换保持单选，输入附言后取消。未触发 `review.submit` 或 `review.start`。
- 390×844 窄屏：评审卡片 x=13、宽365，意见弹窗内容 x=24、宽342，无页面横向溢出；确认／取消位于可视区。人员编辑名单独立滚动，弹窗外层可滚动到保存／取消。1280×800 桌面与 Light／系统暗色已有检查；验收后恢复系统主题及桌面视口。
- 各概览卡片共用 3px 强调边框、图标与标题栏；不再有 Agent Review 独立 tab。单一刷新实际发出 `mr.detail`、`mr.changes`、`mr.review`、`mr.notes`、`mr.tapd`、`mr.ci`、`review.history`，没有派发请求。
